Project 1 · Modules 0 to 2 · 16 topics

Project 1: Plan It and Write the Swift

Create the Xcode project and the GitHub repository, plan the app, and write the Swift code that does the journal's math. A first simple screen shows the results for some sample places and visits.

By the end: An app that runs on iPhone and iPad and shows a summary of sample visits worked out by your own Swift functions, plus a written plan for the whole app.

Set up

  1. Install Xcode. Install Xcode 26 or later from the Mac App Store. Open it once, accept the license, and let it download the iOS platform (the Simulator and the iOS SDK). If the App Store says your macOS is too old, update macOS first.
  2. Sign in. In Xcode › Settings › Accounts, click + and add your Apple Account. A free account gives you a Personal Team, which is enough to run on the Simulator and on your own iPhone. TestFlight and the App Store need the paid Apple Developer Program, which this project does not require.
  3. Create the project. File › New › Project › iOS › App. Product Name: your app's name. Team: your Personal Team. Organization Identifier: reverse-DNS such as com.yourname. Interface: SwiftUI. Language: Swift. Testing System: Swift Testing with XCTest UI Tests. Storage: None (you add SwiftData yourself in 6.5). On the save panel, tick Create Git repository on my Mac.
  4. Set the build settings. Select the project, then the app target. Under General, keep the minimum deployment at iOS 26.0 and make sure both iPhone and iPad are supported. Under Build Settings, set Swift Language Version to Swift 6 and leave Default Actor Isolation at MainActor.
  5. Organize by feature. Create groups (folders) for App, Models, Features/Places, Features/Map, Features/Insights, Features/Settings, Services and Resources. Keep tests in the two test targets Xcode made.
  6. Put it on GitHub. Create an empty repository on github.com (no README, no .gitignore). In Xcode's Source Control navigator (⌘2), right-click Remotes › Add Existing Remote and paste the repository URL, then Integrate › Push. Or, in Terminal inside the project folder: git remote add origin <URL> then git push -u origin main. Add a .gitignore with xcuserdata/, DerivedData/ and .DS_Store.
  7. Commit as you go. Commit after every requirement or two (Integrate › Commit, ⌥⌘C) with a message that says what changed, and push at the end of each session. Your history shows the app growing; requirement 1.5 links to it.

Project 2 · Modules 3 to 4 · 17 topics

Project 2: Model the Data and Build the Screens

Turn the sample data into real Swift types and build every screen in SwiftUI: the list of places, a place's details, the forms, Insights and Settings. The data lives in memory for now; Project 3 saves it.

By the end: All four tabs work with sample data. People can add, edit and delete places and visits until they quit the app.

Topics to cover

TopicCourse lesson and what your app must do
Module 3 · Types, Protocols and Programming Paradigms
3.1Structs: Your Own Value TypesModel values that get copied, such as a draft of a new visit, as structs. At least one conforms to Equatable or Hashable.
3.2Classes and Reference SemanticsUse a class where one shared instance matters, such as the model that holds all places. In your README, say why each of your types is a struct, class, enum or actor.
3.3Enums: Modeling Choices and StateA category enum (String raw values, CaseIterable, an SF Symbol name for each case) and a LoadState enum with associated values: idle, loading, loaded and failed.

3.5Generics: Write It Once, Keep the TypesWrite one generic type or function, such as LoadState<Value>, and use it with two different types.
3.6Error HandlingAn error enum that conforms to LocalizedError, thrown and caught with do-catch, with its message shown to the person.
3.7Concurrency: async/await and ActorsLoad the sample data with async/await (a short Task.sleep stands in for the network), build in the Swift 6 language mode with no warnings, and write one actor.
3.8Programming Paradigms in SwiftIn your README, point to one place in your code for each paradigm: object-oriented, protocol-oriented, functional, declarative and reactive.

4.1Describe the Screen, Not the StepsBuild every screen in SwiftUI. In your README, explain which state change redraws which part of one screen.

4.5Observable ModelsOne @Observable model shared by several screens through the environment.
4.6Lists and Dynamic DataA list of places with sections, swipe to delete, search, and an empty state (ContentUnavailableView).

4.9Motion, Adaptivity, and Liquid GlassAt least one animation that respects Reduce Motion, and one layout that adapts with ViewThatFits or the size class.

Project 3 · Modules 5 to 6 · 18 topics

Project 3: Design It Well and Save Everything

Polish the design with Apple's Human Interface Guidelines, then make the data last: settings, an export file, a SwiftData database and a passcode in the Keychain.

By the end: The app looks right in light and dark mode, at large text sizes and with VoiceOver, and everything people enter survives quitting the app.

Project 4 · Modules 7 to 9 · 21 topics

Project 4: Connect It to the World and Ship It

Add location, the map, photos, live conditions from the internet, an on-device summary, a shortcut and a reminder. Then test, debug and prepare the app for release.

By the end: A complete, tested app with a release plan, ready for TestFlight.
