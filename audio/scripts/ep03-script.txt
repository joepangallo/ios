Alex: Lesson two, testing with Swift Testing. Verification versus validation. Verification asks did we build it right, and tests answer against requirements. Validation asks did we build the right thing, and only people answer that, through TestFlight feedback and real use.
Alex: The testing pyramid sets the mix. Many fast unit tests at the base, fewer integration tests in the middle, a handful of U I tests at the top. A suite leaning on U I tests alone answers too slowly.

Alex: Lesson four, debugging and Instruments. Read the crash before you change code. Xcode pauses on the failing line, the console prints the reason, and the stack trace shows the chain of calls that led there.

Alex: Log with Logger, not print. Print vanishes once the app leaves Xcode, while Logger writes with a level, subsystem and category, so messages can be filtered later and private values stay hidden.

Alex: Lesson five, performance, accessibility and localization. The main thread and the frame budget. The screen redraws sixty times a second, so each frame has roughly sixteen point seven milliseconds. Bodies and handlers run on the main thread, and overrunning the budget causes a hitch, a visible stutter.
Alex: The frame budget lab idea has you scroll a list of study spots, watch frame times against the budget line, decode photos on the main thread and count hitches, then fix and see which change cures which symptom.
